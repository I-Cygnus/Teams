### 주요 수행 업무

**1. 데이터 품질(DQ) 신규 기능 개발**
- 개선활동 전체 현황을 진단규칙-원인분석-개선계획 3계층 트리로 조회하는 [개선활동 상태] 화면을 설계부터 구현까지 단독으로 수행하였습니다. 진행상태 5분류, 12종 필터, 업무영역 권한과 담당자 4역할 기반 조회범위 제어를 포함하며, 프론트엔드·백엔드·엔진 3개 저장소에 걸쳐 개발하였습니다.
- 디스크풀 장애 재발 방지를 위해 PostgreSQL 시스템 정보를 이용한 [테이블 운영 지표] 화면과 REST API를 신규 개발하였습니다. 정확도와 운영 부하의 트레이드오프를 검토하여 근사 함수를 채택하였고, 그 근거와 필요 권한을 배포 절차에 문서화하였습니다.

**2. 운영 장애 원인 분석 및 재발 방지**
- 920만 행 분석 작업 중 발생한 JVM OutOfMemory 장애의 근본 원인을 규명하였습니다. 초기 분석의 오진을 스택 트레이스 해석 원리로 교정하고, 설정 누락 시 무제한 적재로 동작하는 코드와 해당 회귀 커밋을 특정하여, 결과 버퍼가 모든 설정 경우에 100건 이하로 유지되도록 수정하였습니다.
- 커넥션 풀 고갈을 공급-수요 불일치(N vs 2N+2)로 진단하고, 수요 모델 기반 산정식과 3계층 통제 구조를 설계하여 DB 커넥션 총량을 상수 72로 고정하였습니다.
- 운영 DB에서 300GB를 점유하던 테이블을 전체 스캔 없이 시스템 카탈로그 분석만으로 진단하여 디스크 300GB를 회수하였고, 동일 유형 장애를 상시 조회할 수 있는 화면을 구축하였습니다.

**3. 운영·이관·인프라**
- 운영 반영 SQL 9종(메뉴 등록, 코드 보완, 업무영역 초기화 등)을 전부 멱등성과 롤백문을 포함하여 작성하였습니다.
- 폐쇄망 온프레미스 환경에 솔루션을 설치하는 자동화 스크립트 5종(사전점검, 서버 IP 자동 치환, JDK 환경 설정, 이미지 일괄 로드, DB 마이그레이션)과 계정·권한별 실행 절차를 명시한 설치 가이드를 제작하였습니다.
- 레거시 시스템(Java 7, Ant, Oracle 12c) 구동 환경을 복원하고 3층 구조의 빌드 순서를 규명하여 실제 기동을 검증하였으며, Oracle 12c/19c Docker 환경 구축과 `impdp network_link` 방식의 스키마 이관을 수행하였습니다.
- 대기업 고객사 PoC 현장에서 설치·구성·기술지원과 담당자 교육을 담당하였습니다.

**4. 분석 및 문서화**
- 백엔드·프론트엔드·엔진 3개 저장소(화면 1,000개 이상 파일)를 전수 분석하여 대규모 아키텍처 문서를 작성하였고, 인수인계 문서 1종만으로 업무 인계가 가능한 문서 체계를 구축하였습니다.
- 데이터 품질 서비스 워크숍 발표자료를 기술편(30장)과 업무편(45장)으로 이원화하여 제작하였습니다.

## 프로젝트 경험

**I-Poten — AI 모의면접 플랫폼 (2025.10 ~ 운영 중, 3인 팀)**
- Java·Spring Boot 기반 백엔드와 인프라를 담당하였으며, 현재 MAU 600명 이상 규모로 운영 중입니다.
- 인증 로직을 인터셉터 기반 파이프라인으로 일원화하여 컨트롤러 71곳의 중복 코드를 제거하였고, 웹서버 정책으로 인증 트래픽의 90%를 애플리케이션 도달 전에 처리하였습니다.
- 서버 자원(RAM 3.7GiB) 한계로 발생한 메모리 부족을 진단하여 JVM 힙 설정 결함을 수정하고 빌드 파이프라인을 분리, 배포 시 메모리 사용량을 6.4GiB 이상에서 2.9GiB 이내로 안정화하였습니다.
- 전사 보안 점검을 수행하여 치명 결함 3건을 도출·조치하였습니다(비밀키 이미지 번들링 차단, 내부 API 이중 방어 등).

**AsianMart — 커머스·구매관리 통합 운영 시스템 (팀 협업 + 개인 확장)**
- 24개 도메인, 122개 REST API 규모의 시스템에서 발주·입고·재고 등 구매관리 6개 도메인을 신규 설계·구현하였습니다. (커머스 기반은 팀 협업, 구매관리와 관리자 화면 개편은 개인 확장입니다.)
- 입고 확정 트랜잭션에 비관적 락을 적용하여 동시 요청에 의한 재고 중복 반영을 방지하였고, 금액 연산 전반에 BigDecimal을 적용하였습니다.

**IntellyCosm — 성분 분석 서비스 (2인 팀장)**
- 반복 조회 패턴을 계측한 후 Redis 캐싱을 도입하여 평균 응답 시간을 120ms에서 11ms로 91% 단축하였습니다.
